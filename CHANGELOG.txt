PK v0.0.1
    - ISSUES
        - Tree structure would change / folders would be un-requestedly moved into other folders due to bug
        - Blender would hang for minutes when folders were moved when shape key count becomes big (> 600)
    
    - FOUND- AND PROBABLE CAUSES
        - Tree structure was not explicitly stored per object (parent child-relaionships)
        - Tree structure was based on order of shapekeys in list, 
          and the number of children registered per "folder" shape key

        Performance:
        - As it is apparently not possible to directly move Shapekeys to explicit positions
          Changing sort-order (and positions of folders in the list) was done 
          by changing item-order in Shape Keys-list in a loop, one shapekey and one step at the time
        
        - PROBABLE ISSUE: Moving shapekeys in the list at all has been documented 
          in Reddit-treads as costly / labor-intensive for Blender. 

    - REWORK/REFACTOR
        Securing tree-structure:
        - Store tree structure explicitly in Mesh-object

        Performance / Blender not hanging with large lists:
        - No manipulation of the list of shape-keys: leave that as is
        - Create / build a "View model" of the tree-structure using TreeNode objects, 
          that contains the ShapeKeys
        - Create a flatlist of the tree-structure to represent the flatlist 
          that is to be rendered
        - Create an array of shape-key indexes in order of where these 
          shapekeys appear in the flatlist
        - Use UIList - filter_items and flt_neworder / sortorder 
          to display items in the proper order

    - CONCEPTS USED:
        - Create the tree structure in an explicit object-model, 
          using TreeNodes with parent-references and children
        - Use TreeNodes for queries like:
             "do you have children?" "Do you have parents?"
        - Use TreeNodes to derive flatlist from Treestructure
        - Use the direct reference to ShapeKeys, to derive info 
          on those shapekeys where the original code needs this
        - Use flatlist to create a sort-list for Blender UIList, 
          to render ShapeKeys in proper order
        - Use a dictionary for fast queries / fast access 
          to the named items in the list
        - Store the tree-structure in the same way as it was parsed 
          from the ShapeKeys:
            [shapekeyName, shapekeyName,[FolderName,ChildShapekeyName,[ChildFoldername, shapekeyname]]]
        - Update the flatlist with every change
        - Check and create a new NodeTree if another object is selected

v2.0.0
    - MAJOR
        • The add-on now utilizes a robust tree hierarchy internally, so folders can be multi-selected.
        • Extended the "Copy Shape Key" operator to copy drivers and, optionally, override specific properties.
        • The add-on has been organized into multiple Python modules under the `shape_keys_plus` package.
        • The add-on has been fully translated to Japanese.
            To add/modify translations, see the Japanese implementation in `shape_keys_plus/core/translations.py`.

    - MINOR
        • The "Mirror Shape Key" operator has been replaced with one that's compatible with folders and multi-selection.
        • To save a bit of horizontal space, the sidebar's context menus and operator buttons have been merged.
            To access a context menu, click and hold (or drag) the respective operator button.
        • The debug operator "Mutate Folder" is now available via search menu.
        • The normal shape key icon is now hidden to make folders easier to see,
            but can be changed back to any icon in the add-on preferences.
        • Folders icons explicitly set to the default pair will now be updated automatically.
        • Moved the settings for the default folder icon to the add-on preferences,
            so they will persist between projects.

    - PATCH
        • Fixed the Rotation Mode property being reset upon driver variable sorting operations.
        • Fixed inability to retain driver variable data when DriverTarget.id is set to a non-Object.
        • To further speed up shape key operations, the object will be temporarily hidden. This allows all
            operations to be executed in bulk before updating the mesh, meaning performance issues are no
            longer proportional to how many shape keys you have, but rather how long it takes to hide/unhide the object.
            This can be further rectified on the user's end by hiding intense modifiers such as Subdivision.
